# 第 2～5 阶段实施计划

依据用户给定规格，按阶段实现并验证。沿用 brainstorming、writing-plans、test-driven-development、verification-before-completion 工作流程；用户已明确要求继续实现，在现有项目内直接执行。

## 第 2 阶段：配置、解析、动态显示
- ConfigManager 负责项目目录下 JSON 加载和校验；缺失、损坏提示错误，保留上一次有效配置。
- DataParser 处理换行分帧、字段独立类型转换、未知 key 忽略和有限长度缓冲。
- MainWindow 根据 show 生成参数控件；重载配置后新增 key 可直接显示。
- 测试配置故障、分段接收、非法字段、动态新增参数及所有第 1 阶段回归。

## 第 3 阶段：参数编辑
- QTableWidget 提供八列参数编辑，添加、删除、保存。
- 校验 key 唯一、合法类型、数值范围；临时文件加原子替换保存，失败不改变当前配置。
- 保存成功信号触发 UI 重建；测试编辑、保存失败和即时生效。

## 第 4 阶段：曲线
- PyQtGraph 动态建立 curve 参数曲线，每条最多 500 点，x 轴为接收时间。
- 曲线绘制按固定刷新率合并刷新；配置变化重建；string 不支持曲线，在配置中明确校验。
- 测试筛选、有限历史、配置更改、清空和实际窗口布局。

## 第 5 阶段：CSV
- 按配置顺序记录每个有效数据包，缺失字段空白，PC 毫秒时间戳。
- 文件名重复时附加序号，停止/退出安全关闭，写入失败提示并停止。
- 记录中修改配置时停止当前记录，避免同一 CSV 的列定义变更。
- 测试文件内容、重复文件名、错误处理、窗口记录流程和最终全套回归。

路径均相对项目文件目录，不依赖当前终端目录。测试使用临时配置和目录，不覆盖用户数据。真实蓝牙链路仍需目标 MCU 实测。
